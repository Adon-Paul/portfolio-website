# Palette studio

Open **Palette** at the bottom left of any page. Experiments affect only that browser; visitors continue to see the original published colours.

- Main colours expose the common surfaces and accents. All detail colours covers every distinct theme colour used by text, borders, gradients, artwork, shadows and print styles.
- Each row has a native colour picker and a HEX field. Enter or leaving the HEX field applies a valid colour. Three/six digit RGB and four/eight digit RGBA values are supported; a picker preserves existing alpha.
- Reset to original restores all exact published defaults, including after an invalid edit.
- Presets are opt-in. Save combination stores up to eight named palettes locally. Duplicate names replace that combination; delete is explicit.
- Import/export accepts a complete version-1 JSON palette. Unknown/missing keys, non-hex values and unsupported versions are rejected. Download JSON or copy the export field to move a palette to another device.
- Previews persist across navigation/reload when browser storage is available. With blocked storage, editing and export still work for the current page. Stored corrupt data falls back to the originals.
- The dialog itself uses fixed neutral colours to keep controls readable during any experiment. Escape/Close returns focus to the Palette button. No-JS pages show the original theme and hide the editor trigger.

## Single source of truth
`src/content/palette.js` holds named tokens, the exact original values, preset definitions and JSON validation. `PaletteDefaults` emits root CSS declarations into prerendered HTML. CSS and SVG attributes reference these tokens. TechText resolves CSS variables into canvas colours and observes root style changes. Preview colours also update browser theme colour and favicon. The homepage ASCII opening shares Page background for its veil and Accent on light → Accent → Accent hover → Light text for its glow. These are existing palette controls, not a separate animation colour scheme. Saved edits/presets apply to the next opening on reload; reset restores the original glow. The homepage FolderFloat demo also follows the shared Accent, Dark panels, Project surface, Warm dark text, Light text, focus and shadow controls, updating immediately. Homepage guide folders likewise use live Accent and Project surface colours, with text/focus/shadows from shared tokens. PulseHeart uses Accent for the liked heart, Muted light text for idle, Dark panels for the pill and Light text for the count; all follow live palette edits. FluidGlass uses Accent for its tint/markers, Hero grid for its refracted circle/grid and Hero light for its static fallback; palette changes repaint while paused.

Changing the default for everyone requires applying reviewed exported values to this manifest and deploying. A browser preview never writes to GitHub, and no credentials are shipped to the browser. After a deliberate future default change, regenerate the sharing PNG with `scripts/create-share.mjs` before release. That generator reads the same manifest; favicon and HTML theme colour are generated by prerendering. Existing sharing PNG, photos, videos and PDF content are not recoloured by local experiments.

## Preservation and verification
The original palette was captured before refactoring. A fresh browser comparison of text, backgrounds, borders, SVG fill/stroke/gradient stops, shadows and background gradients found **zero differences** across home and all four case-study pages. No existing colour value was intentionally changed. Editor controls are new UI, not part of that baseline.

Browser coverage includes navigation persistence, reset including invalid input, save/load, JSON rejection/roundtrip, blocked and corrupt storage, mobile reflow, native Escape/focus return and accessibility scanning. A separate canvas pixel check verified that TechText draws the edited accent. The main production suite retains all motion/media/static-route checks.
