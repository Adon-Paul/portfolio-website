# Branched site directory

A small branching icon beside the top-left wordmark opens a searchable site directory on every application page. Native links retain opening in a new tab and normal browser navigation. The React Bits BranchedMenu supplied by the owner provides the curved SVG trunk/branches, folding sections, active marker and travelling accent line. It is configured for text labels, palette colours, wrapping rows and keyboard focus; no icon-library wrapper is needed. Attribution/license: `docs/licenses/react-bits-TechText-LICENSE.txt`.

The full-height left sidebar closes on Escape (restoring trigger focus), outside pointer interaction, its close button or selecting a destination. Hidden groups are inert and removed from Tab order. Reduced motion and the saved site pause suppress transitions. At the smallest widths, header links use a second row so the directory button does not overlap them. Existing palette defaults, projects, media, hero effects and wording remain unchanged.

`buildSiteDirectory` in `scripts/site-directory.mjs` reads the actual prerendered pages after `scripts/prerender.mjs` renders them. It emits `dist/site-directory.json` plus a complete `/directory/` HTML document requiring no JavaScript. All public routes, guide heading levels, project sections, homepage studies, downloads and evidence are indexed; decorative/internal element IDs are excluded. Repeated guide subsection names include their parent heading for context. Every generated href is validated against a file and every fragment against a real ID during the build. Additional stable IDs in the React markup provide links to existing project sections, media, processing study and homepage studies. There are no inferred unpublished/private pages or vault imports.

The full index uses native details and links; it is available from the sidebar without JavaScript and remains usable if the enhancement fails. It deliberately needs no app hydration. It uses the published palette defaults. Its URL is in the XML sitemap. The menu/catalog load only on opening. `npm run dev` serves the last built directory files through a Vite middleware; run `npm run build` after changing directory destinations. `npm run build` and `npm run preview` are the authoritative review path.

To retain the strict aggregate JS budget without cutting effects, production guide hydration now reads the already-prerendered article and its contents list from the DOM. Article markdown compilation/loading is unchanged on the server and in Vite development. Production no longer downloads a second copy of every article as a JavaScript module. The complete no-JS articles, native hints, tables, code, static URLs and normal React controls are preserved. The former failed-article-chunk test now verifies complete content and working controls with duplicate article downloads absent. No size threshold was increased.

Coverage: deep-section navigation, marker/branch geometry and folding, keyboard/Escape focus, real hrefs, no-JS full index, failed enhancement fallback, mobile wrapping/overflow/accessibility, palette and paused motion. The build checks every generated destination; existing guide tests cover hydration, contents links, reading controls and accessibility at all four widths.

November 14: owner approved replacing the floating popup with a full-height, edge-attached sidebar (440px maximum, full width on narrow screens), with motion-aware entry. Search, branches, static fallback and native disclosure remain.
